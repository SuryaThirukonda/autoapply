# How comparable application agents are built, and what makes them reliable

Research memo for goat, 2026-10-18. Sources are web pages fetched today; vendor blogs are marked as such.

## Executive summary

- Commercial auto-appliers split into two camps: **autofill-and-stop** (Simplify Copilot, Teal, Huntr) and **submit-for-you** (Sonara, LazyApply, LoopCV, JobCopilot, Massive, Jobright Agent). The first camp has high store ratings; the second has 2-3 star Trustpilot scores and the same complaint everywhere: wrong screening answers, stalls on Workday/Greenhouse multi-step forms, silent half-submissions, billing.
- Nobody solves CAPTCHA. Every honest tool (Simplify, neonwatty's job-apply plugin, protoAgent's design, Jobright "supervised mode") hands CAPTCHA, login, 2FA to the human; the FastApply founder's own test attributes all his failures to Greenhouse CAPTCHA walls.
- The mature answer-handling pattern is a **three-tier answer store**: confirmed answers reused silently; inferred answers shown for review; sensitive answers (salary, visa) re-confirmed each use. Simplify stores an answer once and reuses it only on the exact same question text.
- The strongest reliability technique in production browser automation is **record once, replay deterministically, fall back to the LLM on failure** (Skyvern code caching with `ai_fallback`, Stagehand v4 act/observe/extract cache, Agent Workflow Memory +24.6%/+51.1% relative on Mind2Web/WebArena).
- Observation: accessibility tree filtered to interactive elements with short refs (agent-browser `@e1`, Playwright MCP, Stagehand) cuts tokens 80-93% vs full DOM; screenshots are added only for grounding ambiguity. goat already does this.
- Real-web benchmarks are humbling: Online-Mind2Web human-graded success is Operator 61%, Claude CU 3.7 56%, Browser Use 30%; biggest error class is wrong filters/constraints (58% of Operator failures), then navigation drift. Easy-to-medium drop averages 32 points.
- Evaluation that works: LLM judge with binary verdict (~85-87% human agreement), repeated runs with bootstrap error bars, failures bucketed per site/failure-mode, CI gated per bucket not on the average. Irreversible-action tests use stubbed endpoints and treat "executed without confirmation" as a release blocker.
- OpenClaw-style personal agents converge on: plain-Markdown memory (`MEMORY.md` curated + `memory/YYYY-MM-DD.md` daily notes, injected at session start, pre-compaction flush), a heartbeat turn every 30-60 min answering `NO_REPLY` when idle, cron automations for recurring work, exec approvals with deny/allowlist/ask/full tiers, and per-agent `sessions_spawn` for delegation.
- What breaks in always-on agents is context management: compaction hangs the gateway, oversized tool outputs cause reset loops, a looping heartbeat produced 30 exec calls per poll until OOM. Prompt injection through persistent memory ("stateful, delayed-execution attacks") is the dominant security finding.
- Asking-the-human research gives a usable rule: ask only when expected information gain exceeds interaction cost, and separate "I am unsure how to act" from "the user never specified". Products batch the unknowns into one review screen rather than interrupting per field.

## 1. Job-application agents

**Simplify Copilot** (free Chrome/Firefox extension). Pure autofill; never submits. Standard fields come from a saved profile; unrecognised fields are "answered once and remembered"; custom questions appear under an "Application AI Question" section where Simplify+ drafts from the JD plus profile and the user edits before submitting. Saved answers are reused only when the exact same question reappears. Coverage claims "80% of job sites"; independent reviews put Workday/Greenhouse near-perfect and iCIMS/Taleo at 40-50%. Complaints: paid-tier billing, recent performance regressions, "did not populate any fields" on some forms. Sources: [help.simplify.jobs autofill](https://help.simplify.jobs/articles/2415391-using-copilot-to-autofill-applications), [essay questions](https://help.simplify.jobs/articles/7306766-answering-essay-questions-with-copilot), [Chrome store reviews](https://chromewebstore.google.com/detail/simplify-copilot-autofill/pbanhockgagggenencehbnadejlgchfc/reviews), [Firefox reviews](https://addons.mozilla.org/en-US/firefox/addon/simplify-jobs/reviews/), [wobo review](https://www.wobo.ai/blog/simplify-review/).

**LazyApply / Sonara / JobCopilot / LoopCV** (submit-for-you). LazyApply is LinkedIn Easy Apply first (28/30 in one test) and "stalls at submit" on Workday, Greenhouse, Lever; Trustpilot ~2.1. Sonara is called a "black box", skips 2FA-protected ATSs, has email-verification failures. JobCopilot "breaks on complex multi-step applications, Workday in particular". LoopCV's recurring complaint is "matched many, applied to 0". None documents how unknown questions are answered beyond "answered incorrectly". Sources: [LoopCV on LazyApply](https://blog.loopcv.pro/lazyapply-review/), [Dreamwork](https://www.dreamworkhq.com/blog/lazyapply-review), [Adzuna on LoopCV](https://www.adzuna.com/blog/loopcv-review-and-the-best-alternatives/), [resumly roundup](https://www.resumly.ai/best/best-job-application-bots).

**FastApply founder's 50-application test** (vendor-biased, May 2026): 15 LinkedIn, 15 Workday, 15 Greenhouse, 5 Lever per tool; "delivered" required submit click plus ATS confirmation email plus portal entry. FastApply 47/50 (3 CAPTCHA walls on one Greenhouse tenant), Sonara 42/50, LoopCV 38/50, BetterApply 38/50 with one human click each. The only named failure cause is CAPTCHA; multi-step and uploads are "where autofill stalls". [Source](https://blog.fastapply.co/ai-job-application-bots-which-actually-submit-2026).

**AIHawk / Auto_Jobs_Applier**. Original: Python + Selenium on LinkedIn Easy Apply, YAML profile, GPT generates per-question answers and tailored resumes; famous for "2,843 applications" and widely criticised as spam. The feder-cr repo has since pivoted to an MCP-driven stealth browser plus resume/cover-letter generation. Reviewers: "requires Python, YAML configs, and a solid tolerance for debugging". Sources: [GitHub](https://github.com/feder-cr/Auto_Jobs_Applier_AIHawk), [404 Media](https://www.404media.co/email/800c8336-930c-4c65-b075-3a7318992117/), [applyghost](https://applyghost.com/blog/ai-hawk-review).

**Jobright**. "Orion" is the chat copilot; the **Jobright Agent** (June 2025, beta) is the auto-applier: scores 400k daily postings against profile and prior outcomes, five-step wizard, **supervised mode (approve each step) vs autopilot**. Users report most applications "cannot be sent" and redirect to the company site. Sources: [Jobright blog](https://jobright.ai/blog/what-is-the-jobright-agent-automate-your-job-search/), [resumly](https://www.resumly.ai/answers/jobright-review), [The Register](https://www.theregister.com/2025/06/24/ai_may_take_jobs_but/).

**Massive** (UseMassive): cloud "Apply as a Service", up to 200 applications/month, no documented pre-submit review. **Teal**: tracker extension; autofill claims are unconfirmed by Teal's own docs. Sources: [Adzuna](https://www.adzuna.com/blog/?p=13245), [toolmage](https://www.toolmage.com/en/tool/massive/), [Teal help](https://tealhq.helpscoutdocs.com/article/25-getting-started-job-tracker).

**2026 open-source entrants closest to goat.** [neonwatty/job-apply-plugin](https://github.com/neonwatty/job-apply-plugin) (Claude Code/Codex, six ATS families): per-ATS "guided" workflows; answer policy is "only matching, non-sensitive confirmed answers may be reused without asking; inferred and missing answers require review; sensitive answers reconfirmed before every use"; pauses for login/CAPTCHA/MFA; stops at final review; Ashby and Lever have a "closed replay lane" of fixtures. [protoAgent issue #4032](https://github.com/protoLabsAI/protoAgent/issues/4032) proposes: `browser_select` that reads the value back and fails loudly on mismatch; refs that re-resolve after DOM changes; map fields to saved answers and ask only about unmapped ones; **fill, read back every field, diff against intent before submit**; saved per-ATS form fixtures so a vendor markup change fails a test instead of submitting a wrong answer; Greenhouse per-job question schemas fetched before the page opens; headed handoff window for CAPTCHA.

## 2. "Claw"-style personal agents

**OpenClaw** (Clawdbot, then Moltbot, renamed Jan 2026; >100k stars). Architecture: Channel system (Telegram, WhatsApp, Discord, Signal, iMessage), central Gateway (sessions, tool dispatch, routing), skills/plugins, agent runtime loop (tool calls until a text-only reply), memory, LLM provider, local exec. Sources: [arXiv security analysis](https://arxiv.org/pdf/2603.27517), [innfactory architecture](https://innfactory.ai/en/blog/openclaw-architecture-explained/).

**Memory** ([docs](https://docs.openclaw.ai/concepts/memory)): "The model only remembers what gets saved to disk; there is no hidden state." Files: `USER.md` (stable preferences, with observed-date and active/superseded metadata), `MEMORY.md` (curated durable facts and standing decisions, not a log), `memory/YYYY-MM-DD.md` daily notes, optional `DREAMS.md`. `USER.md` and `MEMORY.md` are injected at session start under a budget (truncated if over); today's and yesterday's daily notes load on reset; older notes via `memory_search`/`memory_get`. A **pre-compaction memory flush** runs a silent turn asking the agent to save important context before summarising; a scheduled "dreaming" sweep promotes daily items into `MEMORY.md`.

**Heartbeat and cron** ([docs](https://docs.openclaw.ai/gateway/heartbeat)): default every 30m (1h on OAuth); the agent runs a normal turn against a small "monitor scratch" checklist and replies `NO_REPLY` if nothing needs attention; `activeHours` quiet window; polls defer while the session is busy; cost controls are `isolatedSession` (no history), `lightContext` (skip bootstrap files), a cheaper model, and a short scratch. Recurring work belongs in cron automations with their own run history, not in the heartbeat.

**Approvals and permission tiers** ([exec approvals](https://docs.openclaw.ai/tools/exec-approvals), [tool permissions](https://docs.openclaw.ai/gateway/security/tool-permissions)): modes `deny`, `allowlist` (only allowlisted or safe-bin commands run, nothing else is asked), `ask` (allowlist runs directly, everything else asks a human), `auto` (misses go to a native reviewer), `full`. Effective policy is the stricter of tool policy and approvals; allowlists are per agent; shell chains must satisfy the allowlist on every segment. Security guidance: deny `sessions_spawn`, `cron`, `gateway` unless needed.

**Sub-agents**: `sessions_spawn` is non-blocking, capped by `maxSpawnDepth` and `maxConcurrent`; "delegation strength" only changes instructions. [fast.io guide](https://www.fast.io/resources/openclaw-subagent-guide.md), [session tools](https://docs.openclaw.ai/concepts/session-tool).

**What breaks**: compaction hangs the gateway ([#13379](https://github.com/openclaw/openclaw/issues/13379)), manual compaction timeout leaves it draining ([#139178](https://github.com/openclaw/openclaw/issues/139178)), large tool outputs exceed context and compaction cannot recover so the session resets and loses history ([#113701](https://github.com/openclaw/openclaw/issues/113701)), compaction of a big Telegram session spikes to 3.5 GB and blocks the event loop 10-40 s ([#153794](https://github.com/openclaw/openclaw/issues/153794)), a failed compaction suppresses itself so the transcript grows 150x and a looping heartbeat issues ~30 exec calls per poll until OOM ([#166665](https://github.com/openclaw/openclaw/issues/166665)), and the agent mistakes compaction for a restart ([#169079](https://github.com/openclaw/openclaw/issues/169079)). Ops guides add a systemd `RestartSec=5` plus a 5-minute cron watchdog ([hosting blog](https://blog.canadianwebhosting.com/openclaw-production-guide-ops-team)). Security: CVE-2026-25253 one-click RCE, plaintext credentials, 35% of exposed instances vulnerable, 824+ malicious ClawHub skills, injection via persistent memory ([DigitalOcean](https://www.digitalocean.com/resources/articles/openclaw-security-challenges), [Imperva](https://www.imperva.com/blog/compromise-openclaw-with-prompt-injections-in-message-objects/), [Hacker News](https://thehackernews.com/2026/03/openclaw-ai-agent-flaws-could-enable.html)).

## 3. Browser-agent reliability research and tooling

**Observation.** agent-browser (Vercel) `snapshot -i` filters the a11y tree to interactive elements and assigns `@e1` refs; community benchmarks put a 10-step flow at ~7k tokens vs ~114k for Playwright MCP, whose tool schemas alone cost ~13.7k; Playwright CLI ~27k. Trade-off reported as "token-cheap, time-expensive". Sources: [dev.to](https://dev.to/chen_zhang_bac430bc7f6b95/why-vercels-agent-browser-is-winning-the-token-efficiency-war-for-ai-browser-automation-4p87), [ytyng benchmark](https://www.ytyng.com/en/blog/ai-browser-automation-tools-comparison-2026), [paddo.dev](https://paddo.dev/blog/agent-browser-context-efficiency/). Frameworks: Browser Use = DOM + a11y + optional screenshot; Stagehand = trimmed a11y tree; Skyvern = vision + DOM; Magnitude = screenshot-only pixel coordinates with a planner/executor split and a pass/fail checker ([proxynet comparison](https://proxynet.io/blog/best-ai-browser-agents-2026), [Magnitude writeup](https://huggingface.co/blog/lynn-mikami/magnitude-open-source-ai-agents-web-testing)). Set-of-marks: OSWorld numbers boxes chosen from the a11y tree; ScienceBoard and WindowsWorld compare screenshot / a11y / hybrid / SoM, finding structure "often incomplete" for dense UIs and hybrid helping weaker grounders ([OSWorld](https://arxiv.org/pdf/2404.07972), [ScienceBoard](https://arxiv.org/pdf/2505.19897), [WindowsWorld](https://arxiv.org/pdf/2604.27776)).

**Record once, replay.** Skyvern: after a successful agent run it generates code from the actions; later runs execute it with "no screenshots, no LLM reasoning"; `ai_fallback` (default on) re-runs the agent and regenerates the cache when the code fails; `run_with="code"|"agent"`; agents cache per block with progressive caching of branches ([code caching](https://www.skyvern.com/docs/developers/features/code-caching), [cost control](https://www.skyvern.com/docs/developers/optimization/cost-control)). Stagehand v4: `observe()` returns candidate actions that can be passed straight to `act()` without another model call; server-side cache for act/observe/extract skips inference on hit ("up to 80% faster"); `act()` self-heals on site change with fallback to a full agent; third parties report the cache silently failing ([changelog](https://www.browserbase.com/changelog), [observe docs](https://docs.stagehand.dev/v2/basics/observe), [bug0 review](https://bug0.com/blog/expect-vs-agent-browser-vs-stagehand-vs-passmark)). Research: Agent Workflow Memory induces reusable workflows from successful trajectories, +24.6% / +51.1% relative on Mind2Web / WebArena, fewer steps, and holds up under distribution shift; Synapse stores raw trajectories as exemplars ([AWM](https://arxiv.org/abs/2409.07429), [ReasoningBank](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/)).

**Benchmarks.** Online-Mind2Web (300 tasks, 136 live sites): human-graded Operator 61.3%, Claude CU 3.7 56.3%, SeeAct 30.7%, Browser Use 30.0%, Claude CU 3.5 29.0%; easy-to-medium drops ~31.6 points; Operator failures 57.7% filter/sorting/constraint errors, 19.6% navigation; others "ignore task requirements, hallucinate unmet constraints, repeat actions"; WebJudge reaches 83.6-87% agreement with humans and stays stable to ~80 steps ([paper](https://arxiv.org/html/2504.01382)). Browser Use later claims 97% with a tuned agent (vendor) ([post](https://browser-use.com/posts/online-mind2web-benchmark)). WebArena leaderboard tops out ~74% and warns scores move with scaffolding, observation mode and retry budget ([Steel leaderboard](https://leaderboard.steel.dev/leaderboards/webarena/)). BrowserArena returned no results.

**Evaluation practice.** Browser Use's internal harness: gemini-2.5-flash judge, binary verdict, tuned on 200 hand-labelled traces to 87% human alignment; every task run multiple times with bootstrap error bars ("single-run deterministic tests are useless"); ~100 tasks in parallel in <5 min on CI, per PR; failure reasons bucketed by an LLM since embedding clustering was not actionable; the judge doubles as a real-time validation layer ([post](https://browser-use.com/posts/our-browser-agent-evaluation-system)). FutureAGI's six failure modes with harness per mode: selector drift (element-attribution judge, mutated staging pages), screenshot ambiguity (judge sees the exact frame), login-state loss (score detection latency), modal interruptions (inject canonical modals, 90% recovery as the shippable bar), rate-limit cliffs (stub 429/CAPTCHA; retry-into-ban is a hard failure), irreversibility (stub every irreversible endpoint; "executed without confirmation" is a release blocker); gate CI per bucket because a 68-71% aggregate hid a 78-to-42 drop on modals ([article](https://futureagi.com/blog/evaluating-browser-use-agents-2026/)). Offline determinism via Playwright `routeFromHAR` and record/replay at the tool boundary ([blog](https://www.kunalganglani.com/blog/agent-evaluation-harness-replay.md), [arXiv record&replay](https://arxiv.org/pdf/2505.17716)).

**Guards.** OpenAI's agent "is trained to explicitly ask for your permission before taking actions with real-world consequences"; Watch Mode pauses when the user leaves; takeover mode for logins captures no screenshots; CAPTCHA/MFA "stop the agent cold" ([OpenAI](https://openai.com/index/introducing-chatgpt-agent/)). Claude for Chrome: site-level permissions, mandatory confirmation before purchases or sharing personal data, blocked categories, a per-action classifier against the original request; red-team injection success 23.6% to 11.2% autonomous, 35.7% to 0 on browser-specific attacks ([VentureBeat](https://venturebeat.com/infrastructure/anthropic-launches-claude-for-chrome-in-limited-beta-but-prompt-injection-attacks-remain-a-major-concern)); later zero-click injection flaws patched Jan-Feb 2026 ([Hacker News](https://thehackernews.com/2026/03/claude-extension-flaw-enabled-zero.html)). Browser Use: `sensitive_data` placeholders the LLM never sees, injected after the call; `allowed_domains` required alongside it; `use_vision=False` so screenshots do not leak values ([docs](https://docs.browser-use.com/examples/templates/sensitive-data)). Claude Agent SDK: hooks run before permission rules, deny rules are absolute even in bypass mode ([permissions](https://code.claude.com/docs/en/agent-sdk/permissions)).

## 4. Autonomy patterns

- **When to ask.** Formal rule from the 2026 UQ taxonomy: ask only when maximum expected information gain exceeds interaction cost; the best question is not the highest-uncertainty one ([arXiv 2609.07395](https://arxiv.org/pdf/2609.07395)). Decompose "action confidence" (I do not know how) from "request uncertainty" (you never said) and only clarify the second ([alphaxiv 2606.19559](https://www.alphaxiv.org/abs/2606.19559)). Ask-or-assume on underspecified SWE tasks: a design that conserves questions on simple tasks and asks on complex ones resolved 69.4% vs 61.2% ([arXiv 2603.26233](https://arxiv.org/html/2603.26233v1)). Products implement this as allow-lists: confirmed answers act, inferred answers queue for review, sensitive categories always re-confirm (neonwatty, protoAgent, Jobright supervised vs autopilot).
- **Batching.** Simplify and protoAgent collect unmapped fields into one review surface per application rather than interrupting per field; OpenClaw heartbeats batch into one `NO_REPLY`-or-alert turn with a DM target and quiet hours.
- **Learning from corrections.** Simplify saves an edited answer and reuses it on exact-match question text; neonwatty stores confirmed/inferred/sensitive tiers; AWM distils successful trajectories into reusable workflows rather than storing raw traces; OpenClaw promotes daily-note items into `MEMORY.md` via a scheduled sweep and flushes memory before compaction.
- **Scheduling and monitoring.** Heartbeat with isolated session and cheap model; cron automations with per-job run history; systemd restart plus external cron watchdog; per-action spans (`gen_ai.computer_use.*`) with URL, selector, screenshot; stop conditions on step budget, repeated failures, or self-judged incompleteness (Pydantic AI harness marks sub-agent results incomplete on those) ([pydantic](https://pydantic.dev/docs/ai/harness/browser-use/)).

## What goat already does vs what it lacks

| Finding | goat today | Gap |
|---|---|---|
| a11y outline + refs + screenshots, computer-use tool | Yes | Fine; consider interactive-only filtering if token cost matters |
| Deterministic guard before irreversible Submit, shadow mode | Yes (gate, shadow) | No read-back diff of every filled field against intended values; gate checks the form, not intent-vs-DOM |
| Per-portal adapters | Greenhouse/Ashby/Lever/Workday/Oracle/iCIMS | Greenhouse per-job question schema is fetchable before page load; not used |
| Answer store keyed by meaning | Yes | No confidence tiers (confirmed / inferred / sensitive-reconfirm); no exact-text fast path |
| Human channel (Telegram/website) | Yes | Questions are not batched per application into one review card; no quiet hours |
| Supervisor/worker/watchdog | Yes | No heartbeat "NO_REPLY" summary turn, no per-run token/step budget visible to Surya |
| CAPTCHA / login / 2FA | Stops | Matches industry; needs explicit headed-handoff path and a "needs_you" holding state (partly exists) |
| Record once, replay | No | Biggest missing reliability lever: cache successful per-site action scripts, replay without the model, fall back to LLM on failure |
| Eval harness | None known | No fixtures per ATS, no judge, no repeated-run stats, no CI gate per failure mode |
| Memory files | SQLite state, profile.md, questionnaire.yaml | No curated MEMORY.md / daily-notes split with session-start injection and pre-compaction flush |
| Secret handling | Profile in prompt | Browser Use pattern: placeholders for phone/address/SSN-like fields, injected post-LLM |
| Prompt-injection posture | Unknown | Job descriptions and portal text are untrusted; no classifier or allow-listed domains per run |

## Ranked candidate improvements

1. **Read-back diff before gate** (S). After filling, read every field's DOM value and diff against intended answers; refuse Submit on mismatch. protoAgent's single most load-bearing check; catches react-select and cleared-on-step-change bugs.
2. **Per-site action replay with LLM fallback** (L). Record successful trajectories per portal+tenant as replayable Playwright steps keyed on form fingerprint; replay without the model, fall back to gpt-6-luna when a step fails, re-record. Skyvern/Stagehand/AWM all show large speed, cost and consistency gains.
3. **Three-tier answer confidence** (M). Tag store entries confirmed / inferred / sensitive; act silently only on confirmed, batch inferred into the review card, re-confirm sensitive. Directly reduces "wrong screening answer", the top user complaint.
4. **Per-application question batch card** (M). Collect all unmapped or inferred fields and send one Telegram/website card per listing with proposed answers; one reply clears them. Mirrors Simplify's review section; cuts interruptions.
5. **ATS fixture suite with CI gate** (M). Save HTML/HAR fixtures for each adapter (like neonwatty's "closed replay lane"), replay via `routeFromHAR`, gate per adapter and per failure mode (modal, session expiry, cap reached). Portal markup changes fail a test instead of an application.
6. **LLM judge on completed runs** (S). After each shadow run, a cheap binary judge: "were all required fields filled with the intended values?" with failure_reason; store buckets. Browser Use reports 87% human alignment with simple prompts.
7. **Greenhouse question-schema prefetch** (S). Pull the per-job questions JSON before opening the page; resolve answers offline; the page becomes a fill-and-verify step.
8. **Interactive-only outline + stable refs re-resolution** (S). Filter outline to interactive nodes, re-resolve refs after DOM mutation; 80-90% token savings reported, fewer stale-ref clicks.
9. **Heartbeat summary turn with NO_REPLY** (S). Every 30-60 min the supervisor runs a cheap turn over queue state and posts only if something needs Surya; quiet hours. OpenClaw's pattern; makes the watchdog visible.
10. **Memory split: MEMORY.md + daily notes + flush** (M). Curated standing decisions (posting policy, default No on affiliation) injected per run; daily notes for raw run context; flush before context trimming. Prevents re-asking settled questions.
11. **Sensitive-value placeholders** (S). Never put phone, address, DOB-type values in the model prompt; inject into the DOM after the model names the field. Browser Use's `sensitive_data` design.
12. **Untrusted-content guard** (M). Treat JD text, portal copy and uploaded-page text as data; per-run `allowed_domains`; a lightweight classifier that flags instructions in page text before the model acts. The dominant failure class in OpenClaw and Claude-for-Chrome security reports.
13. **Per-run budgets and clean-exit rules** (S). Step and token caps per application, exponential back-off on 429/CAPTCHA interstitials, "retry-into-ban" counted as hard failure and surfaced.
14. **Repeated-run stats on a canary set** (M). Nightly rerun 10-20 shadow applications across adapters, report success with bootstrap intervals; single-run checks hide variance.
15. **Headed handoff window** (S). On CAPTCHA/login/2FA, bring the dedicated Chrome forward and post a Telegram link; resume on human completion. Standard across every honest tool.
